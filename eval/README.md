# Наборы вопросов

`sample.jsonl` содержит два собственных учебных текста. Первый соответствует сценарию demo, второй специально показывает, что demo выдаёт заранее заданный ответ и не решает произвольные вопросы. Эти результаты не являются оценкой качества GigaChat.

Для оценки на реальных вопросах ЧГК подготовьте локальный JSONL из источника, который разрешено использовать. В каждой строке: `id`, `question`, `answer`, необязательные `accepted_answers`, `source` и `usage_rights`. Указывайте турнир, автора или URL источника и основание использования. Вопросы с изображениями и аудио сейчас не поддерживаются. Код не скачивает чужую базу вопросов.

```json
{"id":"your-id","question":"Текст вопроса","answer":"Ответ","accepted_answers":["Допустимая формулировка"],"source":"Источник","usage_rights":"Основание использования"}
```

Запуск `uv run chgk-evaluate --mode real --questions eval/your-questions.jsonl --limit 10` делает реальные обращения к GigaChat и расходует квоту. Проверьте настройки модели и лимит до запуска. Ответы и допустимые варианты остаются в оценщике, агенты получают только текст вопроса.

Метрика — совпадение после нормализации регистра, пробелов и ё/е. Она не понимает смысл и может не зачесть эквивалентную формулировку. Отсутствие финального ответа считается неуспехом. Отчёт сохраняет эталон, ответ команды, ошибки и задержки; JSON обсуждений лежит рядом, чтобы спорные результаты можно было проверить вручную.

При ручной проверке обсуждения оценивайте: добавляет ли реплика новую информацию; реагирует ли игрок на уже прозвучавшее; связано ли возражение с условием вопроса; различимы ли роли. Сравнивайте несколько прогонов на одинаковом наборе с зафиксированными моделью и версией промптов. Высокая точность на известных вопросах может включать запоминание моделью исходных ответов.
